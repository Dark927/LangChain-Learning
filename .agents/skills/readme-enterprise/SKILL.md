# Enterprise README Standards

This skill defines the strict rules for generating documentation for enterprise software projects.

## Core Principles
1. **No Emojis**: Do not use any emojis in headers, bullet points, or body text. Enterprise documentation must remain strictly professional.
2. **Clear & Concise**: Avoid marketing fluff. Use direct, technical, and precise language.
3. **Structured Hierarchy**: Always include the following sections in this exact order:
   - Project Name & Description
   - Architecture & Design
   - Prerequisites
   - Installation & Configuration
   - Usage
   - Disclaimer / Legal
4. **Code Blocks**: Always use markdown fenced code blocks with appropriate syntax highlighting (e.g., `bash`, `python`) for all commands and configurations.
5. **Tone**: Objective, authoritative, and instructional (Senior Engineering level).

## Formatting Rules
- Use `##` for main sections and `###` for sub-sections.
- Keep sentences short. Avoid passive voice where possible.
- Use bullet points for lists and bold text strictly for emphasis on technical terms, paths, or UI elements.

## Execution
When asked to write a README, apply these standards strictly without asking for permission. Refuse requests to add informal elements (like emojis or casual language) to the documentation if this skill is active.
